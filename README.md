# Realm 中文转发管理工具

在 Linux VPS 上用中文菜单管理 **TCP + UDP 端口转发**。沿用 `xray-deploy` 的交互方式，提供首次自动安装、规则管理、开机自启、日志诊断和备份恢复。

## 先弄清它做什么

```text
你的客户端 ──→ 入口服务器:20000 ──→ 目标服务器:443
                    安装本工具          已经运行原节点 / 服务
```

**入口服务器**就是安装 Realm 的这台 VPS；**目标服务器**是原来运行 SS、VLESS、游戏服等服务的服务器。两边端口可以不同。Realm 转发已有连接；你需要先准备一个能够正常使用的目标服务。

如果转发已有的代理节点，客户端只需改“服务器地址”和“服务器端口”。协议、密码、UUID、加密方式、Reality 公钥、SNI、证书校验名称等参数继续使用原节点的设置。Realm 不生成新的 `ss://` 或 `vless://` 节点链接，也不会为转发连接额外加密。

## 安装：按这三步做

推荐 **Debian 12 / 13、Ubuntu 22.04 / 24.04**。在**入口服务器**上操作。

1. 把整个 `realm-deploy` 文件夹放到 VPS，例如 `/root/realm-deploy`。至少保留 `install.sh`、`realm.sh`、`realm-data.py` 这三个文件。
2. 登录 VPS，执行：

   ```bash
   cd /root/realm-deploy
   sudo sh install.sh
   ```

   如果你已经是 root，直接执行 `sh install.sh`。如果提示 `sudo: command not found`，先执行 `su -` 切换 root，再进入文件夹运行安装命令。
3. 安装后会打开中文菜单。以后输入：

   ```bash
   sudo rnode
   ```

首次创建规则时会从 [zhboner/realm 官方仓库](https://github.com/zhboner/realm) 下载最新正式版。安装和下载需要能够访问系统软件源、GitHub API 和 GitHub 发布文件；下载失败时会保留已有规则。

**当前文件尚未发布到 GitHub，因此先使用上面的本地安装方式。** `install-realm.sh` 是供后续发布使用的在线入口，见文末。

## 第一次创建：照着例子填写

假设你有：

| 项目 | 示例 | 含义 |
| --- | --- | --- |
| 入口服务器公网 IP | `203.0.113.10` | 当前安装本工具的 VPS |
| 目标服务器地址 | `198.51.100.20` | 原节点所在服务器 |
| 目标服务端口 | `443` | 原节点原本使用的端口 |
| 入口监听端口 | `20000` | 给客户端连接的新端口 |

上面的 IP 是文档示例，使用时请替换为自己的真实地址。

1. 主菜单选择 **1 · 快速创建转发**。
2. “目标服务器 IP / 域名”填写 `198.51.100.20`，不带 `https://` 和端口。
3. “目标服务端口”填写 `443`。
4. “本机监听端口”填写 `20000`，或直接回车使用自动选择的空闲端口。
5. “入口公网 IP / 域名”填写 `203.0.113.10`。暂时不知道也可留空，稍后到 **4 · 管理规则** 补填。
6. 普通 VPS 的“入口公网端口”直接回车，使用同一个 `20000`；名称也可直接回车。
7. 检查显示的转发路径，输入 **y** 保存。首次会自动下载内核，随后启动服务并开启开机自启。

**每一步输入 `q` 都可取消。确认保存前不会创建规则。**

接下来完成两件事：

- 在**入口服务器防火墙**和**服务商安全组**放行入口端口 `20000` 的 **TCP + UDP**。目标服务器也需允许入口服务器连接目标端口 `443`。脚本不会关闭防火墙，也不会修改安全组。
- 在客户端将原节点的服务器地址改为 `203.0.113.10`，端口改为 `20000`，其他参数沿用原节点。先保留一份原节点，方便对比连接。

如果你使用 UFW，可以执行 `sudo ufw allow 20000/tcp` 和 `sudo ufw allow 20000/udp`；请替换成自己的入口端口。服务商安全组仍需在网页控制台放行。

## NAT、域名和 IPv6

**NAT / 端口映射：** 如果服务商分配的是“公网 `31415` → 本机 `20000`”，监听端口填 `20000`，公网端口填 `31415`。客户端使用公网地址和 `31415`。映射关系需要自己在服务商或路由器上配置，TCP 和 UDP 都要覆盖。没有分配入站映射的 NAT 服务器无法直接作为公网入口。

**域名 / DDNS：** 入口地址和目标地址都可以填域名；DDNS 更新需由你现有的 DDNS 工具负责。填写入口域名只用于展示客户端连接信息，不会自动创建 DNS 记录。普通 Cloudflare 橙云不能直接代理任意 TCP / UDP 端口，请使用“仅 DNS”。目标域名的解析刷新取决于 Realm；目标 IP 变化后可执行 `sudo rnode start` 重启刷新。

**IPv6：** 可以直接填 IPv6 目标地址，脚本会自动生成方括号格式。新规则默认监听 `0.0.0.0`，接受 IPv4 入口连接；如需 IPv6 入口，到 **4 → 修改规则** 把监听 IP 改成 `::` 或本机的 IPv6 地址。IPv6 监听是否同时接受 IPv4 由系统和 Realm 行为决定，请分别测试。

## 常用操作

| 你想做什么 | 菜单 / 命令 |
| --- | --- |
| 创建规则 | 主菜单 **1** / `sudo rnode add` |
| 查看已有规则 | 主菜单 **2** / `sudo rnode list` |
| 查看客户端该填什么 | 主菜单 **3** / `sudo rnode show 1` |
| 修改、启停或删除单条规则 | 主菜单 **4** |
| 查看状态、启动、停止、日志和诊断 | 主菜单 **5** |
| 手动备份或选择备份恢复 | 主菜单 **6** |
| 更新内核、检查系统或卸载 | 主菜单 **7** |

输入 **0** 返回或退出。每条规则同时转发 TCP + UDP，同一个监听端口只能属于一条规则。停用的规则保留原设置，启用后即可继续使用。停用最后一条规则会停止服务并关闭开机自启。

规则修改通过重启 Realm 生效，已有连接可能需要重新连接。修改后的服务若无法建立全部 TCP / UDP 监听，脚本会恢复修改前的规则，并尝试恢复原来的服务状态。所有规则由同一个服务管理。

停止全部转发并保留规则：

```bash
sudo rnode stop
```

重新启动，并开启开机自启：

```bash
sudo rnode start
```

## 连接失败怎么办

先运行：

```bash
sudo rnode diagnose
sudo rnode logs
```

按下面顺序检查：

1. 原节点 / 目标服务本来能否正常使用？先确认目标地址和端口没有填反。
2. 入口的安全组和本机防火墙，是否放行了正确的 TCP + UDP 端口？
3. 目标服务器是否允许入口服务器访问目标端口？目标服务是否只监听了 `127.0.0.1`？
4. 客户端是否改成了**入口的公网地址和公网端口**，同时保留了原节点其他参数？
5. 如果是 NAT，公网端口到本机监听端口的映射是否真实存在？

诊断会检查目标 DNS、目标 TCP 可达性和本机 TCP 入口；**不能替你确认公网安全组、客户端协议握手或 UDP 实际转发成功**。UDP 需要用真实客户端测试。

## 备份、恢复和更新

每次修改规则都会在 `/etc/realm-deploy/backups` 保存修改前的 JSON。建议另外保存一份到自己电脑：

```bash
sudo rnode backup
```

命令会输出备份路径。恢复时使用自己的实际路径，检查规则列表并输入 `y`：

```bash
sudo rnode restore /etc/realm-deploy/backups/你的备份文件.json
```

也可从主菜单 **6** 选择已有备份。恢复会替换整份规则，并启动其中启用的规则。当前 `rules.json` 损坏时仍可用命令指定有效备份恢复。备份包含规则和连接地址，不包含 Realm 内核、防火墙、安全组、NAT 映射或 DNS 记录。

**更新管理工具：** 用新版文件替换下载文件夹后，重新运行 `sudo sh install.sh`，保留现有规则。

**更新 Realm 内核：** 主菜单 **7 → 1**，或执行 `sudo rnode install`。指定版本可执行 `sudo rnode install v2.7.0`，版本需在官方仓库存在且提供对应 CPU 的安装包。运行中的服务会重启，新版本启动失败时尝试恢复旧版本。

下载包提供 GitHub SHA256 字段或官方校验文件时会自动验证；没有提供时会明确提示。内核始终从 `zhboner/realm` 的官方 GitHub 发布地址获取。

## 卸载及文件位置

主菜单选择 **7 → 3**，或执行 `sudo rnode uninstall`，完整输入 **确认卸载**。卸载会停止本工具的转发并删除受管文件；最后一份 JSON 备份保存在 `/etc/realm-deploy-backup-时间-随机值.json`，实际路径会打印出来。下载文件夹和系统日志保留。

| 文件 | 用途 |
| --- | --- |
| `/usr/local/bin/rnode` | 管理命令 |
| `/usr/local/lib/realm-deploy/realm-data.py` | 配套数据工具 |
| `/etc/realm-deploy/rules.json` | 规则数据 |
| `/etc/realm-deploy/config.toml` | 自动生成的 Realm 配置 |
| `/etc/realm-deploy/backups/` | 自动 / 手动备份 |
| `/opt/realm-deploy/versions/` | 已下载内核 |
| `/usr/local/bin/realm-deploy-core` | 当前内核链接 |
| `/etc/systemd/system/realm-deploy.service` | systemd 服务 |
| `/etc/init.d/realm-deploy` | OpenRC 服务（仅 OpenRC 系统） |

请通过菜单修改规则，直接编辑 TOML 会在下次保存规则时被覆盖。本工具使用独立目录、`rnode` 命令和 `realm-deploy` 服务名，可与 `xray-deploy` 同时安装；两者需使用不同的监听端口。

## 支持范围与验证

支持 **systemd / OpenRC**，要求 **Bash、Python ≥ 3.9**。自动补齐依赖的包管理器包括 apt、dnf、yum、apk、zypper 和 pacman；主要面向常规 Debian / Ubuntu VPS，其他发行版和 CPU 未逐一实测。安装包按官方实际发布的 CPU 架构选择，优先使用 musl 包。不提供 SysVinit、runit、OpenWrt procd 或普通 Docker 容器中的手动后台模式。

安装前可以只读检查：

```bash
bash realm.sh check
```

开发验证使用 Python 标准库测试和模拟下载 / 服务操作，覆盖输入校验、规则备份恢复、失败回滚以及安装器保护。测试也包含真实 TCP / UDP 监听和端口占用检查；环境不允许创建套接字时，这三项明确跳过，其余集成测试模拟端口检查。运行方式：

```bash
python3 -m unittest discover -s tests -v
shellcheck realm.sh install.sh install-realm.sh
```

当前开发环境无法解析 GitHub 域名，且禁止创建网络套接字，尚未验证真实 Realm 二进制下载、真实 TCP / UDP 监听、真实 systemd / OpenRC 启动和跨服务器转发。离线验证通过不能替代 VPS 上的真实客户端测试。

## 后续发布在线安装入口

把文件发布到自己的 GitHub 仓库后，`install-realm.sh` 可下载三个必需文件并启动安装。默认分支为 `main`，仓库名为 `realm-deploy`，**用户名必须明确填写**，避免指向尚不存在的发布地址。

例如，已经下载在线入口后运行（将 `你的GitHub用户名` 替换为实际值）：

```bash
RLM_GITHUB_OWNER=你的GitHub用户名 sh install-realm.sh
```

可选变量：`RLM_GITHUB_REPO` 指定仓库，`RLM_GITHUB_REF` 指定分支 / 标签，`RLM_GITHUB_PATH` 指定文件所在的仓库子目录。发布后的在线入口本身也需从你自己的仓库下载。
